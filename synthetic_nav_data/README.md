# Synthetic navigation data generator

Fully synthetic, code-generated navigation training data for fine-tuning a VLM
on spatial reasoning (left/right, distance, viewpoint), targeting
[NaviTrace](https://huggingface.co/datasets/leggedrobotics/navitrace) and
[NavSpace](https://github.com/TidalHarley/NavSpace-How-Navigation-Agents-Follow-Spatial-Intelligence-Instructions).
No real 3D scans, no downloaded scenes -- everything (object placement, camera
path, instruction text) is generated by code, so every label is correct by
construction: there is nothing to verify after the fact, because the
instruction is a paraphrase of facts we already computed, never an independent
guess.

## Why this design

See the project's research log for the full reasoning. Short version: NavSpace
and NaviTrace both flagged spatial/goal grounding as their models' main
weakness (paper findings, not our guess). A real NavSpace episode we inspected
also had an instruction that described a 5-turn path whose actual
ground-truth path was two straight segments -- i.e. even the benchmark's own
human-authored data isn't guaranteed self-consistent. This pipeline avoids
that failure mode structurally: the instruction generator is only ever handed
already-computed geometry (`scene["facts"]`), so it can't describe something
that isn't there.

## Pipeline

```
scene_gen.py        procedurally places objects + a discrete-action camera path,
                     computes exact left/right/distance/ordinal facts
scene_template.html  three.js scene, built from scene_gen's output
render.py            headless-Chromium (Playwright) renderer:
                       - start_frame.png          (NaviTrace-style single image)
                       - walk_frame_NN.png         (NavSpace-style first-person frames)
                       - trace_pixels              (2D trace, projected via the
                                                     SAME camera used to render,
                                                     so it's pixel-exact)
instruction_gen.py    turns scene_gen's facts into an instruction sentence,
                       targeting one category: precise_movement /
                       spatial_relationship / viewpoint_shifting
                       (mirrors NavSpace's own category names so eval numbers
                       line up category-for-category)
generate_sample.py    ties it together into one sample.json per episode
```

## Setup

```
./setup.sh
```

Installs playwright + anthropic python packages, downloads three.js.
Needs a Chromium binary; this dev environment already has one at
`/opt/pw-browsers/`. Elsewhere, run `playwright install chromium` and either
rely on auto-detect in `render.py` or set `CHROMIUM_PATH`.

## Generate samples

```
python3 generate_sample.py <output_dir>
```

By default this uses `instruction_gen.template_fallback` (deterministic, no
API key needed) so the pipeline is runnable without credentials. For real
phrasing variety, set `ANTHROPIC_API_KEY` and pass `use_claude=True` to
`build_sample()` -- `instruction_gen.call_claude()` is already wired up for
this; wire the key in as a Modal secret (same pattern as `huggingface-secret2`
elsewhere in this repo) when this moves to batch generation at scale.

## What's built vs. what's next

| Done | Not yet built |
|---|---|
| Outdoor "shapes on a field" scenes (matches the primitive-shapes reference video) | Indoor hallway/room scenes (matches the corridor reference video) -- needed to get closer to NavSpace's actual indoor visual domain |
| precise_movement, spatial_relationship, viewpoint_shifting instruction categories | vertical_perception (needs multi-floor geometry), environment_state (needs conditional logic), space_structure (needs enclosed rooms) |
| Single-sample generation, ~1-2s/sample render time | Batch generation at scale (10k target); real Claude-API phrasing (currently template fallback) |
| NavSpace-style + NaviTrace-style label export from one scene | NaviTrace's real domain is street photography -- this pipeline's synthetic renders won't close that domain gap; NaviTrace still needs the semi-synthetic (real photo + generated label) track discussed separately |
